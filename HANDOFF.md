## Как поднять бота в новом контейнере
1. `python -m venv .venv && .venv/bin/pip install -r requirements.txt`
2. `.env` по образцу `.env.example`. `BOT_TOKEN` лучше держать в переменных окружения облачной среды, а не в чате. Блок-лист сейчас пустой (`BLOCKED_USERNAMES` не задан) — пользователь его снял.
3. `WEBAPP_URL=https://bezzz22.github.io/KORPl`
4. В облачном контейнере aiohttp должен доверять CA прокси: перед запуском подменить `certifi.where` на `/root/.ccr/ca-bundle.crt` (или задать `SSL_CERT_FILE`).
5. Запускать отдельным процессом (`setsid nohup ...`), чтобы не упираться в лимит фоновых задач. Не использовать `pkill -f` с широким шаблоном — он убивает собственную оболочку.

Показывается блоком «Драфт» в боте (`report.draft_block`) и в приложении (`draftBlock`). Порог плохого матчапа 42%, хорошего 56%; выборка шумная, поэтому в тексте всегда видно число игр.
- Роли героев из OpenDota (Carry/Initiator/…) как признак драфта проверил на 284 командах — они почти не отличают выигравших от проигравших, поэтому правил по ним нет.

## Только свои игры
- Регистрация = привязка Friend ID / Steam ID (`/me`, в приложении форма на «Главной»). Бот и приложение разбирают только матчи привязанного аккаунта: чужой матч или без привязки — отказ с объяснением, выбор героя убран. Владение ID не проверяется (любой может ввести чужой); настоящая проверка — вход через Steam OpenID, для него нужен свой сервер.
- Нагрузку это почти не снижает: движок и так разбирает одного игрока, остальные девять идут как контекст (оппоненты, драфт).

## Сборка под катку и жидкое стекло
- Движок считает `threatProfile` (урон по типам, доля автоатак, контроль с признаками БКБ/диспел из `bkbpierce`/`dispellable` констант OpenDota) и ранжирует предметы (`rankCounters`). Результат: `build_plan` (блок «Сборка под эту катку»), `killers[].control` и `counter_why`, находка `build_dispel` (затыкали/рутили, а диспела нет). В тестах константы обрезаны, поэтому там эти поля пустые и советы просто не появляются.

## Тренер на Gemini (бесплатно, через Cloudflare Worker)

Два провайдера: Groq (секрет `GROQ_API_KEY`, модель `openai/gpt-oss-120b`, отвечает за ~1 с) идёт первым, Gemini (секрет `GEMINI_API_KEY`, `gemini-flash-lite-latest`) запасным; порядок меняет переменная `COACH_PRIMARY`. Хватит и одного ключа. Ответ принимается, только если в нём есть «Главное:» и «План на следующую игру:». - Проверка из контейнера: Gemini через Node-fetch отвечал 120 с (прокси контейнера), через curl — быстро; в Cloudflare такой проблемы нет. Модель Groq `llama-3.3-70b-versatile` у этого ключа недоступна, доступны `openai/gpt-oss-120b`, `qwen/qwen3.8-27b` и др.
- Ключи пользователь отправил в чат — их надо перевыпустить после настройки воркера. В репо ключей нет.
- В приложении ответ кэшируется в localStorage на матч, плюс лимит 5 разборов в день на устройство.

## Аегис на главной в 3D (22.10, вечер)
- Пользователь: «лагает, слишком толстый, крутится только влево-вправо». Было: 48 кадров поворота вокруг вертикали (лист 2880×2160) с наложением двух кадров на 2D-холсте и CSS-наклоном, который пересчитывался каждый кадр.
- Стало (`docs/aegis.js`): WebGL — тонкий щит (толщина `DEPTH` 0,075 полукадра) по внешнему контуру модели (`docs/aegis_shape.js`, 160 лучей), лицо — анфас `aegis_still.webp`, спина — кадр «сзади» из раскадровки, отзеркаленный и вписанный в силуэт анфаса (`aegis_back.webp`), кант — бронза со сглаженными нормалями, бегущий блик. Поворот — кватернион: палец крутит в любую сторону (ось поперёк движения, 0,6°/px) с инерцией, сам покачивается по двум осям и раз в 12 с делает оборот, наклон телефона — по двум осям. Двойной тап, долгое нажатие, тап в витрину — как раньше. Без WebGL остаётся картинка. `touch-action: none` на щите (иначе вертикальный свайп листал страницу).
- Найден и старый баг: `IntersectionObserver` присылает пачкой «не в DOM» + «на экране», код брал первое событие — анимация засыпала и дёргалась только от касаний. Теперь берётся последнее. Размер холста — через `ResizeObserver`, не каждый кадр.
- Контур и спина пересобираются `python tools/aegis_shape.py` (нужна раскадровка `aegis_spin.webp`, на главной она больше не грузится). Проверка позы: `aegisPose(yaw)` или `aegisPose([yaw, pitch])`, `aegisState()`; `UI_AEGIS=1 npm run test:ui` снимает анфас, бок, ребро, спину и наискосок.
- **Главная и профиль (живой прогон `node tools/ui-live.mjs 0 home,profile,hero`):** в списке игр помечено «турбо»; у «Формы» подпись «слева последняя»; в «Неделе» строка винрейта только при сравнении с прошлой неделей (иначе она повторяла плитку). Фон: плывущие пятна баз без `filter: blur(70px)` — размытие большого анимированного слоя и стеклянной панели над ним каждый кадр давало рывки на телефоне; мягкость теперь в самом градиенте.
- **Аегис, второй заход («это не щит»):** по чертежу Аегиса (вид сбоку — серп) щит теперь согнут: середина вперёд, верх и низ назад (`SHAPE.bendY` сильнее `bendX`), спина повторяет изгиб, к краю тоньше; умбон — купол с лепестками в центре лица (найден по золоту в анфасе: центр 0,065/−0,028, купол 0,165). Сетка 96×96 на лицо и спину, кант из трёх колец со скруглёнными нормалями. Рельеф чеканки — карты нормалей из яркости (`aegis_front_n.webp`, `aegis_back_n.webp`, тот же `tools/aegis_shape.py`): блики бегут по серебру и бронзе, два источника света и френель по краю. Холст до 3× плотности экрана. Поворот для вершин и нормалей — две формы (`uRot`, `uRotN`): одна общая не линкуется из-за разной точности шейдеров. Частота: цикл на `requestAnimationFrame` без ограничений — на 120 Гц экранах Android будет 120; в Телеграме на iPhone WebKit по умолчанию держит анимации страниц на 60 Гц, со страницы это не обойти.
- Модель на Sketchfab скачиваемая (CC BY 4.0, msta2219), но скачивание только с токеном аккаунта. Если пользователь пришлёт glTF — можно заменить самодельную геометрию настоящей (ужать до ~20–40 тыс. треугольников, текстуры 1024 webp).
