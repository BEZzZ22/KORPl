## Как поднять бота в новом контейнере
1. `python -m venv .venv && .venv/bin/pip install -r requirements.txt`
2. `.env` по образцу `.env.example`. `BOT_TOKEN` лучше держать в переменных окружения облачной среды, а не в чате. Блок-лист сейчас пустой (`BLOCKED_USERNAMES` не задан) — пользователь его снял.
3. `WEBAPP_URL=https://bezzz22.github.io/KORPl`
4. В облачном контейнере aiohttp должен доверять CA прокси: перед запуском подменить `certifi.where` на `/root/.ccr/ca-bundle.crt` (или задать `SSL_CERT_FILE`).
5. Запускать отдельным процессом (`setsid nohup ...`), чтобы не упираться в лимит фоновых задач. Не использовать `pkill -f` с широким шаблоном — он убивает собственную оболочку.

## Драфт (матчапы)
- Движок принимает `matchups` (OpenDota `/heroes/{id}/matchups` для героя игрока) и отдаёт `draft`: винрейт героя против каждого из пяти врагов (от 40 игр), заметки в `texts.json` (`draft_*`). Показывается блоком «Драфт» в боте (`report.draft_block`) и в приложении (`draftBlock`). Порог плохого матчапа 42%, хорошего 56%; выборка шумная, поэтому в тексте всегда видно число игр.
- Роли героев из OpenDota (Carry/Initiator/…) как признак драфта проверил на 284 командах — они почти не отличают выигравших от проигравших, поэтому правил по ним нет.

## Только свои игры
- Регистрация = привязка Friend ID / Steam ID (`/me`, в приложении форма на «Главной»). Бот и приложение разбирают только матчи привязанного аккаунта: чужой матч или без привязки — отказ с объяснением, выбор героя убран. Владение ID не проверяется (любой может ввести чужой); настоящая проверка — вход через Steam OpenID, для него нужен свой сервер.
- Нагрузку это почти не снижает: движок и так разбирает одного игрока, остальные девять идут как контекст (оппоненты, драфт).

## Бот молчит, всё в приложении
- `bot.py` теперь только ставит кнопку «Приложение» в меню и выходит (`python bot.py`, нужны `BOT_TOKEN` и `WEBAPP_URL`). Команд и ответов нет, polling не запускается. Разбор, привязка аккаунта и профиль живут в Mini App (`docs/`).
- `report.py`, `chart.py`, `coach_ai.py` остались в репо и покрыты тестами, но бот их не вызывает. Тренер на Gemini придёт в приложение.
- Шрифт приложения — Manrope (раньше Cinzel/Oswald/Inter), версии файлов в `index.html`/`app.js` подняты до v=9, чтобы сбросить кэш.
- Тексты вычитаны: герои не склоняются по роду (глаголы в прошедшем времени про героев убраны), «байбек» везде заменён на «выкуп».

## Сборка под катку и жидкое стекло
- Движок считает `threatProfile` (урон по типам, доля автоатак, контроль с признаками БКБ/диспел из `bkbpierce`/`dispellable` констант OpenDota) и ранжирует предметы (`rankCounters`). Результат: `build_plan` (блок «Сборка под эту катку»), `killers[].control` и `counter_why`, находка `build_dispel` (затыкали/рутили, а диспела нет). В тестах константы обрезаны, поэтому там эти поля пустые и советы просто не появляются.
- UI: стеклянные панели вкладок и нижней навигации с «линзой», которая едет за пальцем (`glassBar` в `app.js`): зажми и води по панели, вкладки переключаются; на нижней панели переход при отпускании. Свайп влево/вправо по содержимому листает вкладки разбора (кроме графиков).
- Проверял в Chromium (Playwright) с подменой ответов OpenDota; сам Telegram-клиент и вибрацию так не проверить.

## Тренер на Gemini (бесплатно, через Cloudflare Worker)
- `worker/coach.js` — воркер-прокси. Два провайдера: Groq (секрет `GROQ_API_KEY`, модель `openai/gpt-oss-120b`, отвечает за ~1 с) идёт первым, Gemini (секрет `GEMINI_API_KEY`, `gemini-flash-lite-latest`) запасным; порядок меняет переменная `COACH_PRIMARY`. Хватит и одного ключа. Ответ принимается, только если в нём есть «Главное:» и «План на следующую игру:». CORS только для https://bezzz22.github.io, лимит 6 запросов в час на IP и 400 в день на весь воркер, сводка пересобирается из проверенных полей.
- Проверка из контейнера: Gemini через Node-fetch отвечал 120 с (прокси контейнера), через curl — быстро; в Cloudflare такой проблемы нет. Модель Groq `llama-3.3-70b-versatile` у этого ключа недоступна, доступны `openai/gpt-oss-120b`, `qwen/qwen3.8-27b` и др.
- Ключи пользователь отправил в чат — их надо перевыпустить после настройки воркера. В репо ключей нет.
- В приложении ответ кэшируется в localStorage на матч, плюс лимит 5 разборов в день на устройство.

- Каждый ответ проверяется (`problemsOf`): ровно три пункта, нет латиницы и чисел не из сводки, в «Главном» цифра первой проблемы, нет времени покупки предметов, обрывов и многоточий, есть пункт про смерти, если они в сводке. ## Тренер по моментам (последнее, 2026-10-21)
- Пользователь: пересказ цифр бесполезен, нужен разбор «где ошибся». Движок `episodes()` (engine.js) берёт 3–4 самых дорогих момента (смерти, драки без игрока) с фактами: кто убил, драка/один, половина карты (только для смертей в драках, из `deaths_pos`), живые обсы команды, нажаты ли кнопки (`deathNotes`), перевес, сколько лежал, кто умер следом, что потеряли за 2 минуты (здания, Рошан, золото).
- Воркер: формат «Главное / Моменты (— мм:сс Ошибка: … Надо было: …) / План». Факты момента приложение рисует само из `a.episodes`, модель пишет только диагноз. В моменте разрешены только герои, предметы и числа из фактов этого момента (плюс предметы из сборки в «Надо было», сокращения BKB/Pike и т. п.). У Groq 3 попытки, потом Gemini. 60 тестов в `worker/coach.test.mjs`. Кэш ответа в приложении: ключ `coach2:`.
